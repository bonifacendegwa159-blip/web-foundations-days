# Day 8 Reflection

## 1. Most Difficult Concept

The most difficult concept in the course was understanding how to design a system that remains correct when many users make requests at the same time. It is easy to describe what an application should do, but harder to explain how the database, API, and other components work together under heavy traffic. I worked through this by breaking the problem into smaller parts, estimating traffic, and connecting concepts such as transactions, database constraints, caching, and queues to specific problems in the design.

## 2. Improving My QuickNotes Capstone

For my QuickNotes capstone, I would improve the error handling and user feedback. I would make loading, success, empty, and failure states clearer. I would also ensure that repeated submissions do not accidentally create duplicate records. In addition, I would test API requests more thoroughly and document how the frontend behaves when the server is unavailable. I would use the feedback I received on my capstone to prioritise these improvements.

## 3. What I Want to Learn Next

Next, I want to learn more about backend development and databases, especially authentication, SQL transactions, and deploying applications reliably. I also want to practise using tools for API testing, logging, and monitoring. My goal is to move beyond making an application work on my computer and become more confident explaining how it behaves when real users, failures, and increased traffic are involved.
